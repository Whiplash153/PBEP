## ОПРЕДЕЛИТЬ ЦЕЛЬ CLI

CLI — интерфейс командной строки для работы с моделью корзины интернет-магазина. Предоставляет возможность пользователю реализовать цикл от пополнения корзины товарами до оформления заказа. Включает в себя правила перехода между состояниями, обеспечивает контроль переходов состояний и обработку доменных ограничений. Является частью тренировочной программы, для освоения backend инструментов, архитектуры и логики. Для пользователя представлена в виде меню с опциями.  

Меню включает в себя 6 доступных вариантов: 

1. Показать корзину
2. Добавить предмет в корзину
3. Очистить корзину
4. Начать оформление
5. Подтвердить заказ
6. Выйти


## КОМАНДЫ СИСТЕМЫ

1.	### Show cart 

- Тип: Чтение
- Вход: нет
- Изменяет данные: нет
- Состояние: нет
- Ошибки: нет

2. ### Add item

- Тип: Запись
- Вход: Да, вводится item
- Изменяет данные: список items
- Состояние: при добавлении первого элемента переводит корзину из EMPTY в ACTIVE
- Ошибки: недоступно из состояния ORDERED

3.	### Clear cart

- Тип: Запись
- Вход: нет
- Изменяет данные: список items 
- Состояние: переводит корзину в EMPTY
- Ошибки: недоступно из состояния ORDERED

4.	### Start checkout

- Тип: Запись
- Вход: нет
- Изменяет данные: состояние корзины
- Состояние: меняет состояние корзины из ACTIVE в CHECKOUT
- Ошибки: Доступна только из состояния ACTIVE

5.	### Confirm order

- Тип: Запись
- Вход: нет
- Изменяет данные: состояние корзины
- Состояние: меняет состояние корзины из CHECKOUT в ORDERED
- Ошибки: Доступна только из состояния CHECKOUT

6. ### Quit

- Тип: Запись
- Вход: нет
- Изменяет данные: нет
- Состояние: выход из программы
- Ошибки: Доступно только при работе с меню

## ГРАНИЦА ОТВЕТСТВЕННОСТИ

### 1. Что проверяет CLI? 

- Проверяет корректность выбора пункта меню (1–6)
- Преобразует ввод пользователя в ожидаемый тип (например, строку без лишних пробелов)
- Срез пробелов при вводе
- Перехватывает доменные ошибки и выводит сообщение пользователю
- [NO] Не отвечает за бизнес-правила и переходы состояний

### 2. Что проверяет домен?

- Формирует и выбрасывает доменные ошибки при нарушении инвариантов
- Управляет внутренними данными объекта (items, state)
- Отвечает за переходы между состояниями
- Формирует модель корзины
- Формулирует допустимые состояния
- [NO] Не отвечает за общение с пользователями
- [NO] Не отвечает за сохранение данных в файл

### 3. Что делает storage? 

- Читает данные из файла
- Преобразует их в объект Cart
- Сериализирует объект Cart в формат JSON
- Записывает данные обратно в файл
- [NO] Не отвечает за общение с пользователем
- [NO] Не отвечает за бизнес-правила и переходы состояний

### 4. Где происходит обработка ошибок?

- Доменные ошибки формируются в домене и перехватываются в CLI
- Ошибки ввода обрабатываются в CLI
- Ошибки файловой системы выбрасываются storage и могут быть перехвачены на уровне main

### 5. Кто создаёт объект Cart

Main инициирует загрузку модели через Storage.
Объект Cart создаётся внутри Storage (при загрузке или при отсутствии файла) и возвращается в Main.

### 6. Кто инициирует сохранение

Функция сохранения выполняется в Storage, а инициируется в CLI.

## Пользовательские потоки

### 1. Happy path

	1.	Пользователь запускает программу → создаётся Cart (EMPTY)
	2.	Пользователь видит меню
	3.	Add item: “banana” → товар добавлен → Cart ACTIVE
	4.	Add item: “soap” → товар добавлен → Cart ACTIVE
	5.	Start checkout → Cart CHECKOUT
	6.	Confirm order → Cart ORDERED
	7.	Quit → программа завершена

### 2. Negative path (Domain error)

	1.	Пользователь запускает программу → создаётся Cart (EMPTY)
	2.	Пользователь видит меню
	3.	Add item: “banana” → Cart ACTIVE
	4.	Пользователь выбирает Confirm order
	5.	CLI вызывает cart.confirm_order()
	6.	В cart.py проверяется состояние
	7.	Переход ACTIVE → ORDERED запрещён
	8.	Домен выбрасывает OperationNotAllowedError
	9.	CLI перехватывает ошибку и выводит сообщение
	10.	Cart остаётся в состоянии ACTIVE
	11.	Пользователь выбирает Quit
	12.	Программа завершена

### 3. Negative path (Infrastructure error)

	1.	Пользователь запускает программу
	2.	main вызывает storage.load()
	3.	Storage пытается прочитать и десериализовать JSON
	4.	JSON повреждён → возникает ошибка чтения / декодирования
	5.	Ошибка не перехватывается
	6.	Программа аварийно завершается

## Обработка ошибок в CLI

### 1. Ошибки ввода (CLI)

* Невалидный пункт меню (не число) — сообщение “Invalid choice” → возврат в меню
* Номер вне диапазона 1–6 — сообщение “Invalid choice” → возврат в меню
* Пустой ввод меню — сообщение “Invalid choice” → возврат в меню
* Пустой item (включая строку из пробелов) — сообщение “Field is empty” → возврат в меню

### 2. Доменные ошибки (Domain)

* OperationNotAllowedError → CLI выводит текст ошибки → возвращает пользователя в меню

### 3. Ошибки storage

* FileNotFoundError → → фактически не возникает → обрабатывается через возврат новой корзины
* JSONDecodeError → не перехватывается → программа аварийно завершается
* Ошибка структуры данных → не перехватывается → программа аварийно завершается
* Ошибка записи → не перехватывается → программа аварийно завершается
