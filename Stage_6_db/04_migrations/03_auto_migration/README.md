# Task 3: Autogenerating Migrations from Model Changes

## Goal
Learn to use Alembic's `--autogenerate` to create migrations based on changes in SQLAlchemy models.

## What was done
- Added an `updated_at` column to the `Product` model in `models.py`
- Configured `env.py` with `include_object` to prevent Alembic from dropping unrelated tables (`reviews`, `comments`)
- Generated a migration using `alembic revision --autogenerate`
- Verified the generated migration contained only the expected `add_column` operation
- Applied, rolled back, and reapplied the migration to confirm correctness

## Notes
- `--autogenerate` compares the current database state with model metadata.
- Tables not present in models but existing in the database are normally dropped; use `include_object` to prevent this.
- Always review autogenerated migrations before applying them.
- Default values and `onupdate` can be set in the model and will be reflected in the migration.
